## 安全簡化與影響

#25 同時在 `scripts/ci.ps1` 直接執行 `test-runtime.cjs`，也在 `lifecycle-check.cjs` 內呼叫同一套 runtime 測試；這是整合時留下的重複入口，沒有不同測試條件。本輪移除 CI 的直接呼叫，保留 lifecycle 的完整入口及所有原生 runtime、server、UI ownership 斷言。每輪 CI 少跑一次相同測試，不降低覆蓋；不宣稱尚未量測的固定加速比例。

主要二階影響是：CI 查詢回覆不再替使用者改變已暫停工作的歸屬；暫停後繼續會由有效的新查詢確認結果。重試按連續次數計算，避免偶發故障讓之後的正常工作失去自動接續。找不到 origin 時寧可明示等待，避免錯誤 repo 的綠燈被當成本專案結果。沒有增加依賴、改寫持久資料格式或放寬寫入鎖。

## 保留的設計與待評估項目

- **刻意保留**：PID 建立時間核對、未知 owner 的保守阻擋、暫停保留租約、停止／撤銷紀錄及不可變 recovery guard。它們對應既有可重現的資料安全與生命週期問題，程式較長不等於可刪。
- **共同根因**：跨越 `await` 後，可見狀態不等於原操作仍有權修改目前工作。#57／#58 已處理 Leader、UI 與部分 ownership 邊界，舊 CI watcher 未同步補上。可借鏡交易的版本檢查：發布結果前重驗原身分與世代，而不是靠延長 timeout。新增回歸測試已納入 CI，作為這次可直接落地的預防措施。
- **認知成本仍高**：`server.mjs` 同時容納供應商協定、派工、租約協作、GitHub 等待與 HTTP 路由；測試大量以來源區段擷取函式。後續宜在修改相關功能時，逐步把外部等待與供應商契約拆成可直接匯入的模組，再減少字串切割測試。本輪不一次拆完整狀態機，避免讓修復依賴大規模介面變更。
- **契約測試缺口**：#70 的模型設定功能原本依賴已移除的 GET API，上輪真實啟動才發現並修復。未來更新 AionCore 時應保留針對固定版本的真實契約 smoke；一般 CI 不應因此強制呼叫付費模型。本輪只修改 GitHub 等待邏輯，未再次呼叫真實模型。
